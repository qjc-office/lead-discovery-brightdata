QJC 유튜브 채널(@qjc_qjc, 구독자 33,300명)의 다음 영상 주제를 공개 지표로 고르는 파이프라인입니다.
2026-08-04에 실제로 돌렸고, 아래 숫자는 전부 그 실행에서 나온 값입니다.

## 문제

영상 하나를 만드는 데 며칠이 들어갑니다. 그런데 주제는 지금까지 감으로 정했습니다.
어떤 키워드가 실제로 조회수를 내는지, 경쟁 채널이 무엇으로 터졌는지 볼 수 있는 자료가 없었습니다.
주제를 잘못 고르면 제작에 들어간 시간이 그대로 사라집니다.

## 접근

두 축을 같이 봅니다.

- **수요축**: 사람들이 실제로 검색해서 보는 것. 키워드별 검색 상위 영상의 조회수 분포
- **공급축**: 경쟁 채널에서 실제로 터진 것. 최근 업로드를 역으로 뜯어보기

여기에 자사 채널 실적을 기준선으로 얹습니다. "이 주제가 우리 평균보다 큰 자리인가"를 바로 판단하려면
남의 숫자만으로는 부족합니다.

## 랭킹 로직

주제 후보마다 다섯 축을 계산하고, 원천 수치를 CSV에 같이 남깁니다. 점수만 있고 근거가 없으면 쓸모가 없습니다.

| 축 | 계산 | 읽는 법 |
|---|---|---|
| 수요 | 그 주제 영상들의 조회수 중앙값 (로그 스케일) | 자리의 크기 |
| 속도 | 업로드 후 경과일당 조회수의 상위 25% 값 | 지금 오르는 중인가 |
| 레버리지 | 조회수 ÷ 채널 구독자 수의 최댓값 | 작은 채널이 큰 조회수를 냈다면 주제 자체의 힘 |
| 신선도 | 90일 이내 업로드 영상 비중 | 낮으면 최신 버전으로 갈아탈 자리 |
| 경쟁 밀도 | 상위 결과 중 10만 구독자 이상 채널 비율 (감점) | 이미 큰 채널이 잡았는가 |

가중치와 상한값은 전부 `radar_config.json`에 있습니다. 코드를 고치지 않고 바꿀 수 있습니다.

주제 후보는 두 종류입니다. 설정한 검색 키워드 9개(`topic_type=keyword`), 그리고 수집한 제목에서
캐낸 단어와 두 단어 조합(`topic_type=phrase`)입니다. 후자가 "스킬" 같은 신규 주제를 잡아냅니다.

한국어 제목에는 형태소 분석기 없이 접근했기 때문에, 조사를 떼고 서술어 어미와 불용어를 걸러냅니다.
같은 대상을 가리키는 후보("클로드 코드"와 "코드")는 영상 집합이 60% 이상 겹치면 하나로 합칩니다.
제목에 한글이 없는 영상 104건은 순위에서 뺐습니다. QJC가 겨루는 자리는 한국어 검색 결과이기 때문이고,
원본 CSV에는 그대로 남아 있습니다.

## 데이터 출처와 표기

모든 행에 `data_origin` 컬럼이 붙습니다. 실제 수집값과 예시 데이터를 절대 섞지 않습니다.

| data_origin | 뜻 | 이번 실행 |
|---|---|---|
| `yt-dlp:search` | 검색 결과, 조회수만 확보 | 137행 |
| `yt-dlp:search+detail` | 검색 결과 + 업로드일, 구독자 수, 좋아요 | 133행 |
| `yt-dlp:channel+detail` | 자사 및 경쟁 채널 최근 업로드 | 72행 |
| `youtube-analytics-api:own-channel` | 자사 채널 실적 (별도 파일) | 25행 |
| `brightdata:mock` | 합성 예시. 순위 계산에서 기본 제외 | 0행 |
| `brightdata:live` | Bright Data Web Scraper API | 0행 (키 미발급) |

`rank.py`는 `brightdata:mock` 행을 기본으로 버립니다. 포함하려면 `--include-mock`을 명시해야 하고,
그 경우 리포트 첫머리에 몇 건이 섞였는지 적힙니다.

## Bright Data 연결

Bright Data API 키는 아직 발급받지 못했습니다. 환경변수 `BRIGHTDATA_API_TOKEN`이 존재하지만
만료된 값이고, 이번 실행에서 실제로 호출해 확인했습니다. `results/run-log.txt`에 그대로 남아 있습니다.

```
[bd] live probe: POST /datasets/v3/trigger dataset_id=gd_lk56epmy2i5g7lzu0k (token length 36)
[bd] live probe rejected: 401 Unauthorized. Check BRIGHTDATA_API_KEY
```

그래서 코드는 "키가 없어도 지금 진짜 결과가 나오고, 키가 오면 규모가 커지는" 구조로 짰습니다.
`bd_adapter.py`가 기존 자산 `../../bd_client.py`(공식 스펙 구현: `POST /datasets/v3/trigger`,
Bearer 인증, snapshot 폴링)를 그대로 재사용해서 Bright Data 레코드를 이 파이프라인의 영상 스키마로
옮깁니다. 어댑터는 fixture로 end to end 검증을 마쳤고, 로그 하단 부록에 실행 기록이 있습니다.

키가 발급되면 달라지는 것은 규모와 폭입니다.

- **규모**: 지금은 영상 상세 지표를 1건당 약 1.2초에 순차로 가져옵니다. 205건에 3분 39초가 걸렸습니다.
  Bright Data 경로는 트리거 한 번에 대량 병렬 수집이라 키워드와 채널을 열 배로 늘려도 파이프라인 구조가 그대로입니다.
- **폭**: 댓글 대량 수집(주제별 시청자가 실제로 무엇을 묻는지), 다른 플랫폼 교차 신호처럼
  공개 지표만으로는 닿지 않는 데이터가 붙습니다.

전환 방법은 `--bd live` 한 줄입니다. 랭킹 로직은 손대지 않습니다.

## 자사 채널 실적

`YOUTUBE_QJC_*` OAuth 자격증명이 유효해서 YouTube Analytics API로 최근 180일 상위 25개 영상을 받았습니다.
조회수 중앙값 32,109회, 최고 416,080회입니다. 이 값이 후보 주제를 판단하는 기준선이 됩니다.
자격증명이 없거나 호출이 실패하면 공개 지표만으로 그대로 돌아가고, 로그에 그 사실을 남깁니다.

## 실행

```bash
bash run.sh                 # 수집 + 랭킹, Bright Data 자격증명 점검
bash run.sh --bd mock       # Bright Data fixture 경로까지 포함
bash run.sh --bd off        # Bright Data 경로 생략
bash run.sh --rank-only     # 오늘 수집분을 다시 채점만
```

`results/run-log.txt`에 실행 전문이 남습니다. 자격증명은 값이 아니라 존재 여부만 기록합니다.

주제를 바꾸려면 `radar_config.json`의 `keywords`만 고치면 됩니다.

## 제약

- Python 3 표준 라이브러리와 yt-dlp CLI만 씁니다. 설치할 의존성이 없습니다.
- 시크릿은 환경변수로만 읽습니다. 로그에도 파일에도 값을 남기지 않습니다.
- 수집은 공개 페이지가 노출하는 지표만 다룹니다. 요청 사이에 간격을 두고 키워드당 30건으로 제한합니다.
- 제목에서 캐낸 주제 후보는 형태소 분석기 없이 만든 결과라 불용어 목록에 의존합니다.
  새 도메인으로 옮기면 `radar_config.json`의 `stopwords`와 `unigram_blocklist`를 손봐야 합니다.
- 검색 결과는 실행마다 조금씩 바뀝니다. 같은 날 두 번 돌려도 순위가 완전히 같지는 않습니다.
